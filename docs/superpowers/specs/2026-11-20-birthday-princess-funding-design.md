# 박봉의 거지공주 생일선물 펀딩 페이지 — 설계

- 작성일: 2026-11-20
- 상태: 설계 확정, 구현 계획 작성 전
- 참고 프로토타입: hab-poc.vercel.app (구조만 참고, 그림·코드는 가져오지 않음)

## 1. 목표와 범위

친구·동료가 내 생일선물 값을 조금씩 보태 주는 **나 혼자 쓰는 펀딩 페이지**를 만든다. 링크 하나를 메신저(주로 카카오톡)로 보내면, 받은 사람이 로맨스 판타지(로판) 웹툰풍 인트로를 보고 금액을 약속한 뒤 내 계좌로 직접 송금한다.

### 포함

- 로판 표지 + 대화창 방식 인트로
- 펀딩 섹션(선물, D-day, 백마 진행률, 은인 명부)
- 보태기 폼과 송금 안내 화면
- 보태기 기록 저장(Supabase)과 진행률 반영
- 카카오톡 링크 미리보기(Open Graph)

### 제외 (이번 버전에서 만들지 않음)

- 여러 사람이 각자 페이지를 만드는 기능 (`/new`)
- 카드결제 등 실제 결제 연동 (송금은 계좌이체·토스 링크로 직접)
- 선물 구매 인증 사진 업로드
- 링크별 말투 변경 (말투는 하나. 나중에 추가하기 쉬운 구조만 유지)
- 별도 관리자 화면 (Supabase 대시보드로 대체)

## 2. 컨셉

**가난한 왕국의 박봉 거지공주**가 오늘도 창가에서 백마 탄 왕자님을 하염없이 기다린다. 생일은 다가오는데 공주 월급으로는 갖고 싶은 선물을 살 수 없어서, 찾아온 손님(친구)에게 수줍게 도움을 청한다.

- 공주의 말투는 **갸륵한 존댓말**. 본인의 실제 말투가 센 것과 대비되는 반전이 웃음 포인트다.
- 화풍: 로판 웹툰·웹소설 표지풍. 드레스는 예쁘지만 기운 자국이 있고, 티아라에 살짝 금이 가 있다.
- 색: 핑크 + 골드 장식. 제목은 명조 계열(예: 고운바탕), 본문은 고운돋움.
- 표지 제목(설정 가능): 《박봉의 거지공주는 오늘도 백마 탄 왕자님을 기다립니다》
- 받고 싶은 선물: 디올 포에버 쿠션 케이스 골든 메달리온(2026 홀리데이). 사진은 사용자가 직접 준비한 이미지를 쓴다.

### 용어

| 일반 펀딩 용어 | 이 앱의 용어 |
|---|---|
| 보태기 버튼 | 공주님 도와주기 |
| 참여자 목록 | 은인 명부 |
| 진행률 바 | 백마 진행률 (백마가 성으로 달려옴) |
| 금액 프리셋 | 빵 한 조각 5,000원 / 따뜻한 수프 15,000원 / 성 난방비 30,000원 / 직접 입력 |

## 3. 화면과 흐름

```
/ (표지) ──1화 보기──▶ 대화 장면 ──선택지──▶ 펀딩 섹션
                                              │
                                    공주님 도와주기
                                              ▼
                                  /give (보태기 폼)
                                              │ 제출(저장)
                                              ▼
                        /give/done?amount=15000 (송금 안내)
                                              │ 은인 명부 보러 가기
                                              ▼
                                   /?view=funding (인트로 생략)
```

### 3.1 표지 (`/`)

- 공주 표지 일러스트 위에 긴 제목, 아래에 `1화 보기` 버튼.
- `?view=funding`으로 들어오면 표지·대화를 건너뛰고 펀딩 섹션부터 보여 준다.

### 3.2 대화 장면

- 그림 아래 대화창. 대사는 한 글자씩 타이핑되고, 화면을 누르면 타이핑이 즉시 끝나거나 다음 대사로 넘어간다.
- 오른쪽 위 `건너뛰기`는 바로 펀딩 섹션으로 간다.
- 대사와 그림 (기본 대본, `script.ts`에서 수정 가능):

| # | 그림 | 대사 |
|---|---|---|
| 1 | waiting | …오늘도 안 오시네요. 백마 탄 왕자님. |
| 2 | waiting | 우리 왕국은 너무 가난해서… 공주 월급도 박봉이에요. |
| 3 | surprised | 앗, 손님이다! 혹시 왕자님…? 아, 아니시구나… |
| 4 | surprised + 선물 사진 등장 | 사실 생일이 다가오는데… 꼭 갖고 싶은 게 있어요. |
| 5 | pleading | 박봉으로는 도저히 무리라서요… 아주 조금만 보태 주실 수 있을까요? |

- 마지막 대사 후 선택지: `가엾은 공주를 돕는다` → `/give`, `일단 사정을 더 들어본다` → 펀딩 섹션.

### 3.3 펀딩 섹션

- 선물 이름·사진·상품 링크(선택), D-day 배지, 공주 한마디.
- **백마 진행률**: 길 왼쪽에서 오른쪽 성까지 백마가 진행률만큼 이동하는 SVG. 아래에 `백마 진행률 N%`와 목표 금액.
- `공주님 도와주기` 버튼 → `/give`.
- **은인 명부**: 이름과 한마디만 최신순으로 보여 준다(금액은 숨김). 인원수 표시.
- **100% 이상 달성 시**: 백마가 성에 도착한 상태로 멈추고, touched 그림과 함께 "왕자님은 안 오셨지만… 여러분이 제 백마였어요 ㅠㅠ"를 보여 준다. 퍼센트는 실제 값(예: 112%)을 표시하되 백마 위치는 100%에서 멈춘다.

### 3.4 보태기 폼 (`/give`)

- 입력: 이름(필수, 1~20자), 한마디(선택, 100자 이하), 금액(프리셋 3개 또는 직접 입력, 1,000~1,000,000원).
- 숨겨진 함정 입력칸(honeypot). 값이 들어오면 저장하지 않고 성공한 척 완료 화면으로 보낸다.
- 제출 중에는 버튼이 "전하는 중…"으로 바뀌고 중복 제출되지 않는다.

### 3.5 송금 안내 (`/give/done`)

- "N원을 아래로 보내 주세요" + 은행·계좌번호·예금주, `계좌번호 복사` 버튼.
- 토스 아이디가 설정돼 있으면 `토스로 보내기` 버튼(`https://toss.me/{아이디}/{금액}`).
- `amount` 쿼리가 없거나 잘못되면 금액 문장 없이 계좌 안내만 보여 준다.
- `은인 명부 보러 가기` → `/?view=funding`.
- URL에는 금액만 넣고 이름 등 개인정보는 넣지 않는다.

### 3.6 D-day 표시

- 한국 시간(Asia/Seoul) 날짜 기준. 생일 전 `D-N`, 당일 `D-DAY`, 지난 뒤 `D+N`.

## 4. 구조

### 4.1 기술 구성

- Next.js(App Router) + TypeScript + Tailwind CSS, Vercel 배포.
- 데이터: Supabase(Postgres).
- 폰트: `next/font/google`으로 고운바탕(제목), 고운돋움(본문).

### 4.2 설정 파일

코드를 몰라도 고칠 수 있도록 내용은 두 파일에 모은다.

- `src/config/princess.ts`
  - `princessName`, `coverTitle`, `birthday`(YYYY-MM-DD)
  - `gift`: `name`, `image`, `link`(선택)
  - `goalAmount`(원)
  - `account`: `bank`, `number`, `holder`
  - `tossId`(선택)
- `src/config/script.ts`
  - `lines`: 대화 대사와 각 대사의 그림 키
  - `choices`, `presets`, `quote`(펀딩 섹션 한마디), `completeLine`(100% 대사), 오류·안내 문구

실제 이름·생일·목표 금액·계좌는 사용자가 구현 단계에서 채운다. 저장소에는 예시값을 넣는다.

### 4.3 그림 파일

`public/images/`에 아래 이름으로 둔다. 처음에는 핑크 임시 그림(SVG/PNG)을 넣어 두고, 진짜 그림이 생기면 같은 이름으로 덮어쓴다.

| 파일 | 장면 | 비율 |
|---|---|---|
| `cover` | 표지: 상반신, 꽃·반짝이, 위쪽 제목 여백 | 세로 4:5 |
| `waiting` | 창가에서 턱 괴고 기다리는 옆모습 | 4:5 |
| `surprised` | 돌아보며 놀라는 표정 | 4:5 |
| `pleading` | 두 손 모아 부탁하는 갸륵한 표정 | 4:5 |
| `touched` | 눈물 글썽 감동 | 4:5 |
| `gift` | 선물 사진 | 1:1 |

공주 그림 5장은 사용자가 AI 이미지 생성으로 만든다. 같은 공주로 보이게 하는 공통 프롬프트와 장면별 프롬프트는 구현 계획에 포함한다. 특정 기존 작품의 캐릭터나 표지를 따라 하지 않는다. 백마 아이콘은 코드(SVG)로 그린다.

### 4.4 DB

테이블 `contributions` 하나.

| 컬럼 | 타입 | 제약 |
|---|---|---|
| `id` | uuid | PK, 기본값 `gen_random_uuid()` |
| `name` | text | not null, 1~20자 check |
| `message` | text | null 허용, 100자 이하 check |
| `amount` | integer | not null, 1000~1000000 check |
| `confirmed` | boolean | not null, 기본값 false (입금 확인 표시, 대시보드에서 수동 체크) |
| `created_at` | timestamptz | not null, 기본값 now() |

- RLS를 켜고 공개 정책은 만들지 않는다. 브라우저는 DB에 직접 접근하지 않는다.
- 서버만 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`(Vercel 환경변수, 서버 전용)로 접근한다.
- 진행률 합계는 `confirmed`와 관계없이 모든 기록의 `amount` 합이다(약속 금액 기준). 장난 기록은 대시보드에서 삭제한다.
- `/`는 요청마다 새로 렌더링한다(캐시하지 않음). 새 기록이나 대시보드에서 지운 기록이 바로 반영되도록 하기 위해서다.

### 4.5 코드 단위

| 단위 | 역할 | 의존 |
|---|---|---|
| `lib/dday` | 생일과 현재 시각으로 D-day 라벨 계산 | 없음(순수) |
| `lib/progress` | 합계·목표로 퍼센트(표시용 실제값, 위치용 0~100) 계산 | 없음(순수) |
| `lib/validation` | 폼 입력 검사, 오류 문구 반환, 함정 칸 판별 | 없음(순수) |
| `lib/contributions` | 명부 조회, 합계, 저장 (서버 전용) | Supabase |
| `app/give/actions` | 서버 액션: 검사 → 저장 → 완료 화면 이동 | validation, contributions |
| `components/Cover` | 표지 | 설정 |
| `components/DialogueScene` | 타이핑, 탭 진행, 건너뛰기, 선택지 (클라이언트) | script |
| `components/HorseProgress` | 백마 진행률 SVG | progress |
| `components/BenefactorList` | 은인 명부 | 없음 |
| `components/CopyButton` | 계좌 복사 + 실패 시 대체 안내 (클라이언트) | 없음 |

`lib/contributions`는 인터페이스로 감싸 테스트에서 가짜 구현으로 바꿀 수 있게 한다.

### 4.6 링크 미리보기

- `og:title` = 표지 제목, `og:description` = 공주 한마디, `og:image` = `cover` 그림.
- 카카오톡에 링크를 보냈을 때 표지와 제목이 보이는지 공개 전에 확인한다.

## 5. 오류 처리

모든 안내 문구는 공주 말투로 쓰고 `script.ts`에 둔다.

| 상황 | 처리 |
|---|---|
| 입력값 오류 | 브라우저(HTML 속성)와 서버(`lib/validation`) 양쪽에서 검사. 해당 입력칸 옆에 안내. 예: "이름을 알려 주셔야 은인 명부에 적을 수 있어요…" |
| 저장 실패 | 입력값을 유지한 채 폼 위에 안내: "앗, 왕국 우체부가 길을 잃었어요. 한 번만 다시 눌러 주세요." |
| 명부 조회 실패 | 표지·대화·선물·송금 흐름은 정상. 진행률·명부 자리에 "명부를 잠시 못 찾고 있어요"만 표시. |
| 중복 제출 | 전송 중 버튼 비활성화 + "전하는 중…" |
| 스팸·장난 | 길이 제한, 함정 칸, 대시보드에서 삭제 |
| 복사 실패 (카톡 인앱 브라우저 등) | 계좌번호를 선택 가능한 텍스트로 강조하고 "길게 눌러 복사해 주세요" 안내 |
| 목표 초과 | 실제 퍼센트 표시, 백마는 성에서 멈춤 |
| 그림 미준비 | 저장소의 임시 그림 사용 |

## 6. 테스트

- **단위 테스트 (Vitest)**
  - `dday`: 한국 시간 자정 전후, 당일, 지난 날짜
  - `progress`: 0, 목표 미만, 정확히 100%, 초과, 목표 0 방어
  - `validation`: 금액 999/1000/1000000/1000001, 이름 0/20/21자, 공백만 있는 이름, 한마디 100/101자, 숫자가 아닌 금액, 함정 칸
- **서버 액션 테스트**: 가짜 `contributions`로 검사 통과 시 저장·이동, 검사 실패 시 오류 반환, 저장 실패 시 안내 문구 반환, 함정 칸이면 저장하지 않음을 확인.
- **실제 화면 확인**: 개발 서버를 띄우고 375px 폭에서 표지 → 대화 → 선택지 → 도와주기 → 완료 → `/?view=funding` 명부 반영까지 직접 확인.
- **공개 전 체크리스트**
  1. 카카오톡으로 나에게 링크를 보내 미리보기 확인
  2. 카카오톡 인앱 브라우저에서 복사 버튼과 토스 버튼 확인
  3. 개발 중 넣은 테스트 기록을 대시보드에서 삭제
  4. 설정 파일의 예시값이 실제 값으로 바뀌었는지 확인

## 7. 운영

- Supabase 프로젝트 하나를 개발과 실제 운영에 함께 쓴다. 테스트 기록은 공개 전에 삭제한다.
- 입금이 확인되면 대시보드에서 해당 기록의 `confirmed`를 체크한다(화면 표시에는 영향 없음).
